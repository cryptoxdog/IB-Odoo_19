3. Normalization Rules

1. preserve_explicit_contract_language_verbatim_when_supplied
2. derive_only_operational_fields_that_are_mechanically_implied
3. never_convert_architectural_ambiguity_into_an_implementation_default
4. similarly_named_targets_are_not_substitutable
5. discoveries_are_recorded_without_automatically_entering_scope
6. derive_inspection_scope_and_modification_scope_separately_when_not_explicit
7. inspection_scope_may_exceed_modification_scope_only_for_dependency_understanding_and_validation
8. whole_target_readiness_claim_requires_complete_authorized_inventory
9. preserve_unrelated_local_or_user_changes

4. Readiness Gate

Ready When

All applicable conditions must be satisfied:

1. exact_target_is_bound_or_exactness_is_not_material
2. authority_is_resolved
3. semantic_envelope_is_complete_enough_for_mutation
4. unresolved_unknowns_contains_no_material_architecture_or_scope_question
5. required_host_capabilities_for_the_requested_delivery_exist_or_delivery_can_degrade_lawfully
6. inspection_and_modification_boundaries_are_resolved
7. whole_target_readiness_has_complete_inventory_or_is_not_claimed
