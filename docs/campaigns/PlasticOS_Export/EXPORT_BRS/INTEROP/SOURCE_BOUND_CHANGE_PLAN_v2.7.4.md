## 0. Existing operator business locks and proposed source-owner technical realizations

**D-01 Exact company:** For a sale-backed load use the confirmed SO.company; otherwise the exact governing PO.company or actual owned-stock company only when a real source proves it. For third-party non-stock FAS without those native sources, an authorized operator must bind the company with specific source evidence. If multiple valid sources disagree, leave the load held for human reconciliation. No `env.company`, newest-partner, first-by-SO, or nullable-company bypass. Once accepted, company corrections require a governed audit and migration, not arbitrary write.

**D-02 Physical grain:** J1 is one actual ISO container journey per sourced movement cycle, reusable ISO number across separate journeys. J2 associates each attributable actual feeder load, native stock movement, or verified non-stock original to J1. J1 and J2 own no prices, stock posting or carrier booking capacity. Unproven arrival/gate-in/sailing remains Unknown.

**D-03 Booking grain:** E1 reservation and immutable E2 accepted revision belong to Export; E3 counts distinct current equipment slots once, E4 records planned source participation. `booking.slot.load_id` and the old `models/load_extension.py` are explicitly rejected. E3 has optional J1 binding with active-only uniqueness and atomic current revision checks. Foreign keys from Logistics to Export are forbidden.

**D-04 Release authority:** Logistics `assert_can_release_physical_operation` is the central physical source owner; Export can specialize its current-booking constraint through normal downstream Odoo inheritance without creating Logistics -> Export dependency. Guard `_transition`, independent `plasticos.dispatch`, direct/composer sends and cron-driven retries. Old domestic behavior remains allowed; stale Export-specific booking release and packet resend do not. A full packet is NEVER resent by ACK reminder automation; Linda owns a +2h reminder and +4h escalation and the existing four-hour cron interval must change.

**D-05 Linda origin:** A booking message is separate from PO/SO obligations. Add validated `source_kind`/source record/revision for booking requests while keeping old order constraints; booking origin is not a fake PO or reverse FK to Export. Exact native message ancestry, uncertain delivery and authenticated recipient scope control sends and replies. A separate source-kind for exact load ACK reminder/escalation remains Linda-owned and must not be folded into a booking issue or PO resend. No installed API is claimed until owner implementation.

**D-06 Documents authority:** Native `documents.document` retains each source original; PlasticOS Documents alone owns verified/override business acceptance, including all ORM write pathways. A separate typed company/revision/obligation link carries multiple contexts without multiplying originals. Claims, Commission and reminder cron keep transaction-grain semantics; unverified Export scoped evidence cannot satisfy domestic invoice/close.

**D-07 No-code precondition:** Preserve the operator-frozen product decisions without demanding reapproval from imaginary staff. Bind every planned and excluded file to the actual authoritative module/code surface, with explicit interface obligations, sequencing, migration, recovery and tests. Any genuinely NEW material policy choice beyond the frozen design returns to the operator. Completion of planning is not proof of installed runtime behavior or authorization to code. Source drift or a discovered ripple invalidates affected evidence and the dependent change plan.
